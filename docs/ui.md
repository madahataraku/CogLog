# UI

アプリの UI は Forui で作る。テーマと設定の再生成は `app/` で行う。

```bash
dart run forui init
dart run forui theme create
```

`dart run forui theme create` は `app/lib/theme/` を上書きする。テーマの調整は生成後の `app/lib/theme/` に対して行う。

色の方針は次のとおり。

- ベースカラーは Forui の Olive（`app/lib/theme/colors.dart`）。
- アプリの primary は `#F6AD49`。`primaryForeground` はコントラストのため Olive の暗い前景（`#1D1D16`）。
- ボトムナビの選択タブは `primary` ではなく `foreground` を使う（白／暗背景で十分なコントラストを確保するため）。
- `#F6AD49` により合う暖色ニュートラルとして Stone も候補。ベースを差し替えるときは `dart run forui theme create --preset babbbc` を使う。

`dart run forui theme create --preset eabbbc`（Stone なら `babbbc`）のあと、次を手で戻す。

1. `lightColors` / `darkColors` の `primary` を `#F6AD49`、`primaryForeground` を `#1D1D16` にする。
2. `darkColors` の `destructiveForeground` と `errorForeground` をどちらも `#171717` に戻す。
3. 再生成後の `theme.dart` には選択色の設定が無いので、現在の `_bottomNavigationBarStyle` を復元し、`lightTheme` と `darkTheme` の両方へ渡す。アイコンと文字の選択色はどちらも `foreground` にする。

## アプリの根

`app/lib/main.dart` は次の順で組む。

1. `MaterialApp` の `supportedLocales` は `L10nHelper.supportedLocales`。
2. `localizationsDelegates` の先頭に `appLocalizationsDelegates` を置く。これは `L10nHelper.delegate` と、`material_ui` の `GlobalMaterialLocalizations.delegates` である。`MaterialApp` が後ろへ足す英語だけの delegate より先に、`ja` をサポートする delegate を置く。
3. `FLocalizations.delegate` を同じリストに含める。
4. `builder` で `FTheme`、`FToaster`、`FTooltipGroup` の順に子を包む。明暗はプラットフォームの明るさに合わせ、`lightTheme` と `darkTheme` を使う。
5. 画面の入れ物は `FScaffold` を使う。

## ボトムナビゲーション

アプリの主導線はボトムナビゲーションである。項目はホーム、メーター記録、推移、運動履歴、目標設定の 5 つ。

- `FBottomNavigationBar` をシェルの `FScaffold.footer` に置く。
- タブは同列に切り替え、履歴には積まない。
- `FBottomNavigationBar` を `FScaffold.footer` に置くときは、双方の上ボーダーが二重にならないよう調整する。
- ソフトウェアキーボード表示中（`MediaQuery.viewInsets.bottom > 0`）はボトムナビを隠す。
- シェルの `FScaffold` がキーボード inset を一手に扱い、子へは `MediaQuery.removeViewInsets(removeBottom: true)` で bottom inset を渡さない（ネストした画面 `FScaffold` の二重縮小を防ぐ）。

Forui の Widget と、Cupertino または Material の Widget は同じ木に置いてよい。

## 推移

- ヘッダは `FHeader`、タイトルは「推移 / Trends」。
- 期間と比較プリセットはそれぞれ `FSelectMenuTile`。グループ Select と旧・指標組 Select は置かない。
- 比較 Select とグラフのあいだ（グラフ直上）に、条件に応じて `FButton` を置く。グラフ上へのオーバーレイはしない。許可リクエスト・履歴許可・OS 設定は、身体指標を含む比較の選択時のみ。再試行は系列の読込失敗時に比較を問わず出す。
- 許可リクエスト未実行かつ未許可（または Android の部分許可）のとき「ヘルスケアの表示連携」ボタンを出し、その直下に体重・体脂肪率をグラフへプロットする旨のサブテキストを置く。一度リクエストしても granted にならないときは許可ボタンを隠し、OS 設定ボタンを出す。
- グラフは `Expanded` 内の Syncfusion `SfCartesianChart`。カード化しない。異単位は左右の Y 軸。軸または凡例付近に単位を付ける。凡例（指標名と系列色）を常時出す。ツールチップで値と代表日付を示す。実線／点線はドメイン定義どおり。
- 画面が足す外側 Padding は上・左右 0、下のみ 16（ホーム基準＝明示の外周 Padding を載せすぎない）。
- 身体を含む比較で身体指標は許可済みだが Android の履歴許可が無く、表示期間が直近 30 日を超えるときは、履歴許可の再要求ボタンを出す。

## 運動履歴

- 月ヘッダの vertical 8 は維持する。旧リストの隣接余白 8 はカレンダー化に伴い廃止する。
- カレンダーは月曜始まりで、選択月の日付のみを示す（前後月の日付セルは出さない）。
- セル高さは 56 論理ピクセル。スタンプは primary 色の塗りつぶし円（直径 8）。同一日に 2 件以上あるときは件数もカレンダー上に出す。
- 読込中は月ヘッダを出し、カレンダー領域に進捗表示する。失敗時はエラーと再試行を出し、空のカレンダーと誤認させない。
- 運動履歴詳細で同一日に複数件あるときは、件数位置（何件中の何件目か）を出し PageView でめくる。1 件のときは件数表示とめくりを出さない。

## 運動履歴詳細・編集

- 詳細ヘッダ右上（suffixes）に編集（pencil）と削除（trash）。処理中は無効。
- 写真は本文最上部。高さは画面高の最大約 30%（ConstrainedBox）。
- 計測／記録は `FTileGroup`（カロリー・運動時間・距離・平均速度・運動した日時）。メタは別 `FTileGroup`（撮影・保存・作成開始）。グループ間 24。
- 日時は全文日時。編集の運動した日時は DateTime Picker（日付のあと時刻）。
- 削除・編集の破棄は `view_confirm_dialog`（`showFDialog`、`barrierDismissible: false`）。
- 編集は詳細の子ルート。遷移は `ScreenNavigation` のみ（`openExerciseHistoryEditAndWait`）。

## 置き場所

- 1 画面だけの Widget は、その screen パッケージに置く。
- 2 画面以上で使う Widget とデザインシステムは `view_*` に置く。
- モデル未ダウンロード誘導ダイアログは、ホームとメーター記録（後続）で共用するため `view_model_download_guidance` に置く。
- 読み取り中モーダルは、メーター記録と運動履歴編集で共用するため `view_meter_reading_progress` に置く。
- 共用の不定ローディングスピナー（`threeArchedCircle`）は `view_loading_spinner` に置く。
- ホーム初回読み込み中ダイアログはホーム専用のため `screen_feature_top` に置く。
- 削除確認と編集破棄確認は共用のため `view_confirm_dialog` に置く。内容外周の余白はモデル未ダウンロード誘導・読み取り中と同じ 16 論理ピクセルとする。
- 起動時のテーマ接続だけを `app` に残す。画面の中身を `app/lib/main.dart` に増やさない。

## 読み取り中モーダル

- Forui の `showFDialog` を使う。
- `barrierDismissible` は `false`（外側タップでは閉じない）。`useRootNavigator: true` でルート Navigator に載せ、ダイアログ障壁によりボトムナビ操作も受け付けない。
- 内容は `view_loading_spinner` の `AppLoadingSpinner`（`threeArchedCircle`、64 論理ピクセル四方・primary）、読み取り中文言、目立たない中止ボタン（`FButton` の `secondary`）。確定進捗ゲージと％は出さない。
- ダイアログ内容の外周に 16 論理ピクセルの余白を置く。
- DialogRoute の完了は `MeterReadingProgressLauncher` 内だけが行い、自身の Route のみを外す（最上位が別ダイアログでも誤って閉じない）。画面から `Navigator` を直接呼ばない。
- プラットフォームの戻る／pop は中止と同じ（Dialog 内 `PopScope`）。読み取り中は運動履歴編集の破棄確認を出さない。
- プレビュー上オーバーレイや画面内インラインの読み取り中表示は出さない。
- 背面へ移っても読み取りは継続し、前面復帰後もモーダルを維持する。
- メーター記録と運動履歴編集で同一部品を使う。


## ホーム読み込み中ダイアログ

- Forui の `showFDialog` を使う。`barrierDismissible` は `false`。`useRootNavigator: true` でルート Navigator に載せ、背面操作を受け付けない。
- プラットフォームの戻る／pop では閉じない（`PopScope(canPop: false)`。中止ボタンは置かない）。
- 初回 Ready 前のみ表示する。期間合計とワンポイントアドバイスの読込完了（Ready）で閉じる。タブ選択・前面復帰の再読込では出さない。
- 内容外周は 16 論理ピクセル。読込中は `AppLoadingSpinner`（`threeArchedCircle`、64・primary）と文言「読み込み中です…」／`Loading…`。失敗時は同ダイアログで「ホームの読み込みに失敗しました」／`Failed to load home` と再試行ボタン。
- 背面の本文は描画したままダイアログを重ねる。
- DialogRoute の完了は `TopHomeLoadingLauncher` 内だけが行い、自身の Route のみを外す。画面から `Navigator` を直接呼ばない。

## コーチマーク（チュートリアル）

- 再利用 UI は `view_coach_mark` に置く。専用全画面ウィザードは作らない。
- ハイライト表示は `tutorial_coach_mark`（`TutorialCoachMark` / `TargetFocus`）を pub 依存で使う。`showFDialog` は使わない。
- 実効版はルート `dependency_overrides` で固定する（path フォークしない）。
- ハイライト対象は `CoachMarkTarget` で `CoachMarkTargetId` を登録し、表示時の矩形を `TargetPosition` に渡す。キー未解決時は画面中央の矩形にフォールバックする。
- 吹き出し（タイトル・本文・主／副ボタン）は `TargetContent` の子として `view_coach_mark` が描く。穴の外に十分な余白があれば、穴が下寄りなら上・上寄りなら下に置く。撮影プレビューやグラフなど大きな穴で余白が足りないときは、画面内に収まるよう `ContentAlign.custom` で端に固定し、主／副ボタンを操作できる位置を確保する。ライブラリ標準の SKIP は隠す。
- 外側タップ・ハイライト外タップ・背面スクロール・穴下のフォーム操作は無効。メイン段階3のスキップはメイン完了扱い。表示中の OS 戻るはライブラリにより無効。
- 読み取り中モーダル表示中はコーチマークを出さない／隠す。提示済みにはしない。撮影タブの離脱・読み取り開始で閉じるのは撮影／編集文脈だけとし、目標設定文脈やホームのメイン連鎖など他画面のコーチマークは破棄しない。
- ホームのメイン段階1→2→3は同一表示コールバック内で連鎖する。外部から強制破棄されたとき（ホーム離脱・背面と重なる場合を含む）は同じ段階を pending に戻して復帰時に再開する。`CoachMarkLauncher` は `disableBackButton` ルートの `removeRoute` 後始末が終わるまで dismiss 完了を返さない（同期 complete だと直後の再 show の `Navigator.push` と競合し、初回起動の段階1→2 が欠ける）。
- メイン段階1の穴は期間集計と指標切替の外カード全体、段階2の穴は目標達成率と今週の目標達成日数の外カード全体とする。カード内の個別ウィジェットだけを穴にしない。
- 目標設定文脈は一日あたり・週間日数・自動更新の3手を同一タブ上で連鎖する。段階3の次へで目標タブへ移ったあと、読込完了かつタブ選択時に評価する。表示失敗やタブ離脱では session の提示済みを戻し、同一プロセスで再評価できるようにする。
- チュートリアル表示中はモデル未ダウンロード誘導を出さない。抑止では誘導の提示済みにしない。
- アプリ設定の「チュートリアルを再表示」は通知設定とデータ管理のあいだの `FTile`。

## モデル未ダウンロード誘導

- Forui の `showFDialog` を使う。
- `barrierDismissible` は `false`（外側タップでは閉じない）。
- アクションは縦並びで「閉じる」と「モデルを準備」。
- DialogRoute の完了（pop）は `ModelDownloadGuidanceLauncher` 内だけが行う。画面から `Navigator` を直接呼ばない。
- OS LLM（Foundation Models / Gemini Nano）向け (A) は、ホームとメーター記録で共用の `view_model_download_guidance` を使う。準備中も「閉じる」は常時有効。
- LFM VL 向け (B) は、 (A) が成立しないときだけホームが Ready になったあとに同じ部品でダイアログを出す（OS LLM 非対応または画像入力非対応で、LFM VL は端末対応だが未ダウンロードのとき。LFM VL 自体が非対応の端末は対象外。`main` に画面中身を増やさない）。
- 同一プロセスの再表示禁止は (A) と (B) で別フラグとする。
- (B) のモデル準備は Wi-Fi のみ開始する。モバイル回線では開始せず、ダイアログ内に通信条件エラーを出す（「閉じる」は有効のまま）。
- ダイアログ内容の外周に 16 論理ピクセルの余白を置く（枠に文字・ボタンが密着しないようにする）。
- 準備中は確定進捗ゲージ（0〜1）と％表記を出す。進捗はダウンロード済みバイト／全体容量（Content-Length または推定容量）に基づき、1% 単位で進める。進捗イベント前はゲージを 0 で示す。(B) のみ準備中は「閉じる」を無効化する。
- 容量不足／通信失敗は区別できる文言。その他失敗は共通文言。いずれもダイアログ内に出し閉じない。

## 目標設定

- 一日あたりの運動時間・消費カロリー・走行距離は、「1日あたりの運動目標」タイトルのカードにまとめる。説明「未設定の欄は空のまま保存できます。」も同カード内に出す。
- 週間の目標運動日数のまとまり（ラベル・説明・選択）は別カード。目標の自動更新のまとまりも別カード。保存ボタンはカード外。
- 保存ボタン下には 16 論理ピクセルの余白を置き、ボトムナビへ密着しないようにする。
- 保存成功後はホームタブへ切り替える（失敗・入力不正のときは目標設定タブに留まる）。
- 週間の目標運動日数: 欄タイトルは「週間の目標運動日数」。説明文でホームの残り日数表示と、連続達成・自動更新判定への利用を示す。入力は `FSelect` のプルダウン。「設定しない」と 1〜7 を選ぶ。初期値・未保存時は「設定しない」。自由入力は置かない。

## ホームの期間集計と指標

- 本日・今週・今月の期間集計と指標切替（カット選択メニュー）を一つの外カードにまとめる。
- 指標切替はタブ（走行距離 / 消費カロリー / 運動時間）。初期選択・順序は従来のプルダウンと同じ。選択結果が同一カード内の 3 期間表示に反映される。
- 3 期間は現行と同じ順序・期間ラベル・単位表示を維持し、外カードの中でも本日／今週／今月それぞれの個別カード枠を残す。
- メイン段階1のコーチマーク穴は、この外カード全体を対象にする。

## ホームの週間目標達成日数

- 目標達成率（見出し＋3 リング）と今週の目標達成日数を一つの外カードにまとめる。外カードに追加タイトルは付けない。
- 今週の目標達成日数のまとまりは外カード内の内カードにする。期間カットに依存せず常時表示する。
- メイン段階2のコーチマーク穴は、この外カード全体を対象にする。
- 表示可のとき: 見出し「今週の目標達成日数」、バー上部に `達成日数:n日 / 目標日数:m日`、`LinearProgressIndicator`（`value` は `min(n/m, 1.0)`）、バー下部に `n < m` なら `目標達成まであとx日！`（`x = m - n`）、`n >= m` なら `今週は目標達成済！`。
- semantics: `n < m` のとき達成・目標・残り日数。`n >= m` のとき達成済が伝わる（「残り0日」のみでは足りない）。
- 週間の目標運動日数が未設定、または正の一日あたり目標が無いとき: 内カード内に見出し＋設定誘導文言を出す（タップでの目標設定遷移はしない）。

## アチーブメント

- ホームの `FHeader` 右上（`suffixes`）にアチーブメントアクションを設定の左隣へ置く。アイコンは trophy。新規アチーブメントがあるとき、アイコン右上に件数なしドットを重ねる。押下でアチーブメント画面へスタック遷移する。
- アチーブメントはホームタブ内の子ルート（`/achievements`）。`FHeader.nested` と戻るアクションを使う。
- 一覧は系統セクション無しのフラットリスト。各行を枠で囲み、項目間余白は 16 論理ピクセル、水平パディングは 16。未開放は名前を隠し、達成条件と `LinearProgressIndicator` を出す。開放済みは名前・達成条件・MAX の進捗バーを出し、背景色と枠色を未開放より強調する。新規行には件数なしドットを付ける。
- 一覧の読込成功（Ready）後に最終閲覧日時を更新する。読込失敗時はエラー文言と再試行を出す（最終閲覧日時は更新しない）。

## アプリ設定とデバッグ

- ホームの `FHeader` 右上（`suffixes`）に、アチーブメントの右隣へ設定アクションを置く。押下でアプリ設定へスタック遷移する。
- アプリ設定・通知設定・データ管理・OSS ライセンス・デバッグはホームタブ内の子ルート。`FHeader.nested` と戻るアクションを使う。
- アプリ設定は設定項目の一覧（上から通知設定、チュートリアルを再表示、データ管理、ライセンス、デバッグ）を `FTileGroup` とし、その下にアプリ情報専用の別 `FTileGroup`（バージョンと端末 OS。表示のみでタップでは遷移しない）を置く。ヘッダ直下の余分な余白は出さず（本文 `ListView` の top padding を 0）、二つの `FTileGroup` のあいだには 24 論理ピクセルの間隔を置く。
- 通知設定・データ管理・OSS ライセンスも、アプリ設定と同様に本文 `ListView` の top padding を 0 にし、ヘッダ直下の余分な余白を出さない（タイル内など子の意図した Padding は残す）。デバッグ画面はこの余白方針の対象外とする。
- データ管理はエクスポート／インポートの操作を持つ。処理中は確定進捗を出し操作を無効化し、エクスポート・ファイル選択・インポート適用中はシステム戻るでも画面を閉じない。インポートの全置換確認は `view_confirm_dialog`（`barrierDismissible: false`）を使う。
- 通知設定は ON/OFF を切り替え、許可拒否時は案内テキストのみを示す（再要求ダイアログなし）。
- OSS ライセンスは依存ライブラリの一覧と本文。空のときは空状態メッセージを出す。遷移は `ScreenNavigation` 経由とする。
- デバッグは、診断結果とアプリ内ログを縦スクロールで示す。
- デバッグの LFM VL 再ダウンロードは、開始前に `view_confirm_dialog`（`showConfirmDialog`、`barrierDismissible: false`）で確認する。キャンセル時は何も変えない。実行中は画面内に確定進捗ゲージと％を出し、キャンセル操作は置かない。ボタン無効の主条件は、再ダウンロード実行中・診断実行中・LFM VL が端末非対応（readiness が unavailable）とする。メーター VL の prepare／generate 競合は開始時の live チェックで拒否し、拒否理由文言を画面に出すがボタンは無効化しない（再試行可。初期化時の busy スナップショットだけに依存しない）。説明文言は LFM VL 優先スイッチと同様にボタン近傍へ出す。成功／失敗／実行中のステータス文言は Entity の `redownloadStatusText` をそのまま出し、Body で phase から再合成しない。確定後に診断表示を更新する。
- アプリ内ログは、編集不可（`readOnly`）で選択・コピー可能な複数行テキスト領域とする。領域は固定高さで内部スクロールし、親の縦スクロールと独立して追える。並びは古い行が上・新しい行が下。追記時の自動スクロールはしない。ストアが空でも空のテキスト領域を出し、空状態専用文言は出さない。

- 画面から `Navigator` を直接呼ばない。遷移は `ScreenNavigation` 経由とする。

## メーター記録カメラ

- メーター記録タブの第一画面はアプリ内カメラである。ボトムナビはシェルの `FScaffold.footer` のまま表示する。
- プレビューはヘッダー下〜操作列上の領域を全面で埋める。カメラの表示縦横比を保ち、余白のレターボックスは作らず、はみ出しは中央基準で切り取る。
- プレビュー直下（ボトムナビの直上）に、ライブラリから選ぶ操作と丸いシャッターを置く。シャッターは通常のカメラアプリと同様の円形ボタンとし、中央に置く。ライブラリ操作とシャッターのあいだには十分な間隔を置く。
- 「ライブラリから選ぶ」ラベルは改行しない。狭い幅ではテキストサイズを縮めてシャッターと視覚的に重ならないようにする（受け入れの狭い幅は既存 step1 狭幅 Golden の surface）。
- カメラ権限拒否時はプレビューを出さず、設定案内とライブラリ選択を出す。権限拒否時もライブラリラベルは改行せず他コントロールと重ならない。
- 読み取り結果画面のメッセージはドメインの言葉「手打ち案内」に従い `FAlert`（variant は primary）で出す。撮り直すは `FButton` secondary、登録は primary とし横並びにする（既存 step2 幅では折返さない）。登録／撮り直すの下には 32 論理ピクセルの余白を置き、ボトムナビへ密着しないようにする。
- 読み取り中は「読み取り中モーダル」に従う（プレビュー上オーバーレイの読み取り中表示は使わない）。
