# プロダクトとドメイン

## プロダクト

CogLog は、エアロバイクの運動履歴を記録し、減量を支える Flutter アプリケーションである。

- 記録の対象は、据え置き型のエアロバイクで行った運動である。
- 主機能は、運動履歴の記録である。
- 利用者が支える目的は減量である。
- 画面の文言は日本語を優先し、英語も持つ。
- 対応するのは Android と iOS である。
- ヘルスコネクトおよび Apple ヘルスケアと連携する。

## 運動履歴

1 件の運動履歴は、1 回の乗車であり、メーターパネル写真 1 枚である。永続化した 1 件は運動履歴 ID を持つ。

- まだ運動履歴になっていない撮影は、新しい運動履歴になる。
- 運動履歴になった写真を撮り直すときは、前の写真と撮影日時を上書きする。別の運動履歴は作らない。上書きしたときは、走行距離、運動時間、平均速度、消費カロリーを読み直す。

1 件は記録日時を持つ。利用者がまだ手で変更していないときの決め方は次の順である。

1. メーターパネル写真の撮影日時を使う。
2. 撮影日時が取れないときは、作成開始日時を使う。

利用者は記録日時を手で変更できる。一度手で変更した記録日時は、その後に写真を上書きしても維持する。手で変更していない記録日時は、上書き後の写真について上の順で決め直す。記録日時の手変更は、永続化した運動履歴が持つ。

作成開始日時は、メーター記録フローで写真（撮影またはライブラリ選択）が確定した時点とする。

同一の未保存フロー内で写真を取り直して再確定した場合は、作成開始日時を再確定時点で更新する。

永続化した運動履歴の撮影日時は必須である。写真のメタデータから撮影日時が取れないときは、作成開始日時を撮影日時として保存する。

1 件は次の計測値を必ず持つ。保存するのはこの 1 組であり、手打ちする前の読み取り値は持たない。

| 属性 | 単位 |
| --- | --- |
| 走行距離 | km |
| 運動時間 | 時、分、秒 |
| 平均速度 | km/h |
| 消費カロリー | kcal |

永続化した運動履歴は、上記に加えて次を必ず持つ。

| 属性 | 意味 |
| --- | --- |
| 運動履歴 ID | 1 件を一意に指す |
| 保存日時 | 初めて永続ストアへ書いた日時。編集では変えない |
| 作成開始日時 | その運動履歴の作成を開始した日時。メーター記録では、写真（撮影またはライブラリ選択）が確定した時点とする |
| 撮影日時 | メーターパネル写真の撮影日時 |
| 記録日時 | 期間へ振り分ける日時 |
| 記録日時の手変更 | 記録日時を利用者が手で変えたか |
| メーターパネル写真 | 1 件につき 1 枚 |

運動時間の時、分、秒がすべて 0 の運動履歴は保存できない。

いま定義する単位系はこの 1 つである。あとから別の単位系を追加できる余地を残す。追加する単位系の中身は、この文書に書いてから実装する。

### メーターパネル写真の保持

- 画像の本体は、アプリ専用のローカルファイル領域に置く。運動履歴の永続レコード（データベース）へ画像バイナリは入れない。
- 永続レコードは、運動履歴 ID に対応する写真ファイルを特定できる参照だけを持つ。
- 1 件につき写真ファイルは 1 つとする。撮り直しは、同じ運動履歴 ID のファイルを置き換える。置き換え前のファイルは残さない。
- 運動履歴を削除したら、対応する写真ファイルも削除する。
- ヘルスサービスや、端末の共有アルバム・フォトライブラリへは、写真を自動では出さない。

### OS バックアップ

- 永続化した運動履歴のデータベースと、メーターパネル写真は、iOS および Android の端末バックアップ（iCloud バックアップ、Google の自動バックアップなど）の対象に含める。
- 置き場所は、各 OS がアプリデータとしてバックアップする領域とする。バックアップから除外する設定は付けない。
- フォトライブラリや共有アルバムへの自動保存とは別である。
- Android の自動バックアップには、アプリあたりおおよそ 25 MB の容量上限がある。上限を超えると、その後のバックアップは更新されない。
- 上限を超えても、端末上に既にある運動履歴と写真は消えない。問題になるのは、上限超過後に追加した運動履歴がバックアップへ載らず、端末交換などで古いバックアップから復元したときに、その追加分が戻らないことである。
- 上限超過後も新しい運動履歴をバックアップへ載せ続けられるようにする手段（画像圧縮・再エンコード、選択的バックアップなど）は、必要に応じて別作業とする。この節では実装しない。

### 運動履歴の編集と値の入り方

運動履歴は編集できる。削除もできる。永続ストアに対する操作は、作成・読み出し・更新・削除である。

値の入り方は 2 通りある。

- メーターパネルを撮影し、読み取りエンジンで解析する。
- 手打ちする。読み取りエンジンが使えないとき、読み取りで走行距離、運動時間、消費カロリーが揃わないとき、運動時間が 0 のとき、読み取りミスを調整するときに使う。

読み取りエンジンは、次の順で 1 つずつ使う。先のエンジンで走行距離、運動時間、消費カロリーが揃い、運動時間が 0 より大きいときは、その結果を使う。運動時間が 0 の読み取りは、揃った結果にしない。平均速度がパネルに無いことは、次のエンジンへ進む理由にしない。パネルに無く、運動時間が 0 より大きいときは計算する。運動時間が 0 のときは平均速度を計算しない。

| 端末 | 順 |
| --- | --- |
| iOS | VisionOCR、次いで FoundationModel |
| Android | ML Kit、次いで Gemini Nano |

どちらも使えないとき、どちらも走行距離、運動時間、消費カロリーが揃わないとき、または運動時間が 0 のときは、手打ちする。各エンジンが読めた走行距離、運動時間、平均速度、消費カロリーは合わせて、手打ちの初期値にする。同じ項目を複数のエンジンが読んだときは、あとに読めたエンジンの値を使う。運動時間が 0 より大きく、平均速度が無いときは、計算した平均速度を初期値にする。運動時間が 0 のときは、平均速度を未入力のまま手打ちへ進む。

平均速度は、メーターパネルに表示があるときはその値を使う。表示が無く、運動時間が 0 より大きいときは、走行距離と運動時間から次の式で求める。運動時間が 0 のときは、この式を使わない。

```text
平均速度 (km/h) = 走行距離 (km) / 運動時間 (時)
```

運動時間は時、分、秒を時に直してから割る。パネルの値と計算結果がずれるときは、パネルの値を使う。

## 期間集計

期間の境界は、端末の現地時刻で切る。記録日時を端末の現地時刻へ直した日時で、運動履歴を期間へ振り分ける。

| 期間 | 境界 |
| --- | --- |
| 本日 | 現地日付の 0:00 から、翌日 0:00 の直前まで |
| 今週 | 月曜 0:00 から、次の月曜 0:00 の直前まで |
| 今月 | その月の 1 日 0:00 から、翌月 1 日 0:00 の直前まで |

期間集計が合計するのは次の 3 つである。

- 走行距離
- 消費カロリー
- 運動時間

集計期間は利用者が選ぶ。ホームが最初から示す切り口は、本日、今週、今月の 3 つである。利用者が選ぶ期間も、同じ現地時刻で切る。

運動履歴を編集または削除したあとは、期間集計をやり直す。

## ヘルスサービス

CogLog からヘルスサービスへ書くのは、運動の種類と、運動履歴の次の 3 つである。

- 種類はサイクリング
- 走行距離
- 運動時間
- 消費カロリー

書き込みに成功した運動履歴は、ヘルスサービス上のサイクリング 1 件に対応する。対応するサイクリングがあるとき、運動履歴の編集はそのサイクリングの更新、削除はそのサイクリングの削除である。

ヘルスサービスとの完全な同期は必要としない。書き込み、更新、削除が失敗しても、CogLog の運動履歴の保存、編集、削除は完了する。失敗した反映をやり直す振る舞いは持たない。

CogLog がヘルスサービスから読む身体の指標は次のとおり。入力元はヘルスサービスである。

| 指標 | 単位 | ヘルスコネクト | Apple ヘルスケア |
| --- | --- | --- | --- |
| 体重 | kg | WeightRecord | bodyMass |
| 体脂肪率 | % | BodyFatRecord | bodyFatPercentage |
| 除脂肪体重 | kg | LeanBodyMassRecord | leanBodyMass |

身体の指標の単位系も、あとから追加できる余地を残す。追加する単位系の中身は、この文書に書いてから実装する。

CogLog は、読んだ体重、体脂肪率、除脂肪体重を保存しない。推移を表示するときにヘルスサービスから読む。許可が無いとき、または許可が撤回されたあとは、その指標の点を置かない。指標の削除は、ヘルスサービス側の削除に従う。

同じ現地日付に指標が複数あるときは、計測日時が最も遅い値をその日の値にする。

## 推移

推移では、利用者が選んだ期間について、運動と身体の指標をグラフに示す。導線はボトムナビの左から 3 番目（ホーム、メーター記録の次）である。

| 期間 | 日数（本日を含む） | 点の間隔 |
| --- | --- | --- |
| 過去 30 日 | 30 日 | 1 日ごと |
| 過去 3 カ月 | 90 日 | 7 日ごと |
| 過去半年 | 182 日 | 14 日ごと |
| 過去 1 年 | 365 日 | 28 日ごと |

初期表示は過去 30 日である。画面上は運動グループと身体グループを切り替える。両グループは同時に重ねない。

バケットの揃えは、今日を終点に選んだ間隔で過去方向へ区切る。期間先頭側に割り切れない端数があるときは、期間の最も古い側を短いバケットにする。各点の代表日付はバケットの末尾日（今日側）である。端数バケットもその末尾日を代表日付とする。

過去 30 日・1 日ごとのときの点の意味:

| 指標 | 1 日の点 |
| --- | --- |
| 運動時間 | その日の運動履歴の合計 |
| 走行距離 | その日の運動履歴の合計 |
| 消費カロリー | その日の運動履歴の合計 |
| 体重 | その日の最終の計測値 |
| 体脂肪率 | その日の最終の計測値 |
| 除脂肪体重 | その日の最終の計測値 |

7 / 14 / 28 日ごとの 1 点は、そのバケット区間に入る値を集約する。運動は区間内の合計（履歴が無ければ点なし）。身体は区間内の計測のうち計測日時が最も遅い値（計測が無ければ点なし）。

運動履歴が無い日（または区間）は、運動時間、走行距離、消費カロリーの点を置かない。身体の指標が無い日（または区間）は、その指標の点を置かない。線は指標ごとに引く。点が 0 個または 1 個の指標は線を引かない。

- 日次（1 日ごと）: 代表日（現地日付）が隣り合う区間は実線。あいだに点の無い日がある区間は点線。空いた日に点は置かない。
- 間引き（7 / 14 / 28 日ごと）: 表示上となり合う 2 点について、バケット列上で隣り合う（間に空バケットが無い）なら実線、間に空バケットがあれば点線。

グループ内は同単位の指標のみ同時表示できる。運動グループは単位がすべて異なるため常に 1 指標ずつとし、初期選択は消費カロリーである。身体グループは体重と除脂肪体重（kg）を同時表示でき、体脂肪率（%）は kg 組と同時に出さない。身体の初期選択は体重＋除脂肪体重である。

推移タブはヘルス許可の状態にかかわらず常に表示する。身体グループ選択時に、明示ボタンで体重・体脂肪率・除脂肪体重をまとめて許可リクエストする（自動では出さない）。未許可の指標の点は置かない。系列の読込に失敗したときは、表示中のバケットと系列を空にし、グループを問わず再試行できる。許可リクエストを一度実行しても granted にならないとき（iOS の unknown 含む）は、許可ボタンを隠し、身体グループで OS の設定画面を開く導線を付ける。Android で一部指標だけ許可されているときは、許可済み指標の点だけを置き、未許可分の再リクエストボタンを残す。

Android ではヘルスの履歴許可が無いとき、身体指標の読取開始を直近 30 暦日に切り詰める。過去 90 / 182 / 365 日の期間では、それより古い計測に点を置けない。境界をまたぐバケットも取得できた範囲だけで集約する。身体指標の許可済みでも履歴許可が無いときは、履歴許可を再要求する導線を出す。許可リクエスト時には履歴許可もあわせて要求する。

体重と除脂肪体重を同時表示するときは、指標名と系列色の凡例を出して判別できるようにする。

データを取り直す契機は、画面を表示するたび、および期間またはグループを変更したときである。

## 画面

| 画面 | 示すもの |
| --- | --- |
| ホーム | カット選択メニューと本日・今週・今月の期間集計。期間集計の下にワンポイントアドバイス（吹き出し左・アドバイザー右）、未ダウンロード検出時は誘導ダイアログ、その下に目標達成率を置く。右上はアチーブメント（設定の左）と設定から、それぞれアチーブメント画面・アプリ設定へ遷移する |
| アチーブメント | 獲得状況の一覧をカタログ順のフラットリストで示す。未開放は名前を「？？？？？」とし達成条件と進捗バーを出す。開放済みは名前と達成条件を出す。読込失敗時はエラーと再試行を出す |
| メーター記録 | アプリ内カメラでメーターパネルを撮影するか、カメラ画面上の操作で写真ライブラリから 1 枚選び、読み取りまたは手入力で計測値を入れて運動履歴を作成する。写真と撮影日時は必須。作成開始日時は写真が確定した時点とする。編集画面の「撮り直す」は下書きを破棄してカメラ画面へ戻る。取り直して再確定したときは作成開始日時をその時点で更新する |
| 運動履歴 | 上段で月を選び（月サマリ）、下段にその月（記録日時の現地暦月）の運動履歴リストを作成開始日時の降順で示す。リストは消費カロリー・運動時間・走行距離・作成開始日時を出し、30 件単位の無限スクロールとする。Pull to refresh で現在の月を再取得する。項目を選ぶと運動履歴詳細へ遷移する。選んだ月に 1 件も無いときは、画面中央に「この月の運動履歴がありません。メーター記録から、メーターパネルの撮影または手入力で運動履歴を作成してください。」と案内する |
| 運動履歴詳細 | 消費カロリー、運動時間、走行距離、作成開始日時、メーターパネル写真、撮影日時、平均速度、記録日時、保存日時を示す。記録日時の手変更が真のとき、記録日時に「（編集済み）」を付ける。どの項目を編集したかの内訳は出さない |
| 目標設定 | 一日あたりの運動時間・消費カロリー・走行距離の目標に加え、目標の自動更新の有効／無効と自動更新レベルを同一保存で永続化する。各指標は未設定のままにでき、0 も設定できる。自動更新は初期無効、レベル初期はふつう。オフでもレベルは選べる |
| アプリ設定 | アプリ全体の設定一覧。上から通知設定、ライセンス、デバッグへの導線を持つ。最下部にアプリ情報をグループ化されたリストとして表示する。OS のアプリ設定画面（権限など）とは別である |
| 通知設定 | 通知の ON/OFF。初期は OFF。ON にしたときに OS の通知許可を求める。許可が拒否されているときは案内のみを示し、再要求ダイアログは出さない |
| OSS ライセンス | 依存ライブラリ名の一覧と各ライセンス本文。空のときは空状態メッセージを出す。戻るとアプリ設定へ戻る |

| デバッグ | 端末上 LLM の readiness・ネイティブ status/reason/message・生成／準備プローブ結果・例外（型名と cause を含む）・アプリ内ログを示す。再診断とログ消去ができる。準備状態に関わらず接続プローブを試し、AICore 問い合わせ失敗の原因を端末上で追えるようにする |
| 推移 | 選んだ期間の、運動と身体の指標のグラフ。導線はボトムナビ左から 3 番目。初期期間は過去 30 日。運動／身体のグループ切替と、同単位の指標切替。読込失敗時は再試行。身体グループではヘルス許可・履歴許可・OS 設定導線と、複数指標時の凡例を持つ |
