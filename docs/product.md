# プロダクトとドメイン

## プロダクト

CogLog は、エアロバイクの運動履歴を記録し、減量を支える Flutter アプリケーションである。

- 記録の対象は、据え置き型のエアロバイクで行った運動である。
- 主機能は、運動履歴の記録である。
- 利用者が支える目的は減量である。
- 画面の文言は日本語を優先し、英語も持つ。
- 対応するのは Android と iOS である。
- ヘルスコネクトおよび Apple ヘルスケアと連携する。

## 運動履歴

1 件の運動履歴は、1 回の乗車であり、メーターパネル写真 1 枚である。永続化した 1 件は運動履歴 ID を持つ。

- まだ運動履歴になっていない撮影は、新しい運動履歴になる。
- 運動履歴になった写真を撮り直すときは、前の写真と撮影日時を上書きする。別の運動履歴は作らない。上書きしたときは、走行距離、運動時間、平均速度、消費カロリーを読み直す。

1 件は運動した日時を持つ。利用者がまだ手で変更していないときの決め方は次の順である。

1. メーターパネル写真の撮影日時を使う。
2. 撮影日時が取れないときは、作成開始日時を使う。

利用者は運動した日時を DateTime Picker（日付の選択のあと時刻の選択）で変更できる。自由な文字列入力では変えない。Picker で変更したときは運動した日時の手変更を真にする。一度手で変更した運動した日時は、その後に写真を上書きしても維持する。手で変更していない運動した日時は、上書き後の写真について上の順で決め直す。運動した日時の手変更は、永続化した運動履歴が持つ。

全文日時の表示形式はドメインの言葉「全文日時」に従う。

作成開始日時は、メーター記録フローで写真（撮影またはライブラリ選択）が確定した時点とする。

同一の未保存フロー内で写真を取り直して再確定した場合は、作成開始日時を再確定時点で更新する。

永続化した運動履歴の撮影日時は必須である。写真のメタデータから撮影日時が取れないときは、作成開始日時を撮影日時として保存する。

1 件は次の計測値を必ず持つ。保存するのはこの 1 組であり、手打ちする前の読み取り値は持たない。

| 属性 | 単位 |
| --- | --- |
| 走行距離 | km |
| 運動時間 | 時、分、秒 |
| 平均速度 | km/h |
| 消費カロリー | kcal |

永続化した運動履歴は、上記に加えて次を必ず持つ。

| 属性 | 意味 |
| --- | --- |
| 運動履歴 ID | 1 件を一意に指す |
| 保存日時 | 初めて永続ストアへ書いた日時。編集では変えない |
| 作成開始日時 | その運動履歴の作成を開始した日時。メーター記録では、写真（撮影またはライブラリ選択）が確定した時点とする |
| 撮影日時 | メーターパネル写真の撮影日時 |
| 運動した日時 | 期間へ振り分ける日時 |
| 運動した日時の手変更 | 運動した日時を利用者が手で変えたか。いずれかの編集項目を保存して更新が成功したときも真にする（運動した日時以外の編集でも真）。真のあいだは写真上書き後も運動した日時を維持する |
| ヘルスワークアウト ID | 対応するサイクリングの外部識別子。任意。書き込み成功時のみ持つ |
| メーターパネル写真 | 1 件につき 1 枚 |

運動時間の時、分、秒がすべて 0 の運動履歴は保存できない。

いま定義する単位系はこの 1 つである。あとから別の単位系を追加できる余地を残す。追加する単位系の中身は、この文書に書いてから実装する。

### メーターパネル写真の保持

- 画像の本体は、アプリ専用のローカルファイル領域に置く。運動履歴の永続レコード（データベース）へ画像バイナリは入れない。
- 永続レコードは、運動履歴 ID に対応する写真ファイルを特定できる参照だけを持つ。
- 1 件につき写真ファイルは 1 つとする。撮り直しは、同じ運動履歴 ID のファイルを置き換える。置き換え前のファイルは残さない。
- 運動履歴を削除したら、対応する写真ファイルも削除する。
- ヘルスサービスや、端末の共有アルバム・フォトライブラリへは、写真を自動では出さない。

### OS バックアップ

- 永続化した運動履歴のデータベースと、メーターパネル写真は、iOS および Android の端末バックアップ（iCloud バックアップ、Google の自動バックアップなど）の対象に含める。
- 置き場所は、各 OS がアプリデータとしてバックアップする領域とする。バックアップから除外する設定は付けない。
- フォトライブラリや共有アルバムへの自動保存とは別である。
- Android の自動バックアップには、アプリあたりおおよそ 25 MB の容量上限がある。上限を超えると、その後のバックアップは更新されない。
- 上限を超えても、端末上に既にある運動履歴と写真は消えない。問題になるのは、上限超過後に追加した運動履歴がバックアップへ載らず、端末交換などで古いバックアップから復元したときに、その追加分が戻らないことである。
- 上限超過後も新しい運動履歴をバックアップへ載せ続けられるようにする手段（画像圧縮・再エンコード、選択的バックアップなど）は、必要に応じて別作業とする。この節では実装しない。

### 運動履歴の編集と値の入り方

運動履歴は編集できる。削除もできる。永続ストアに対する操作は、作成・読み出し・更新・削除である。

編集で利用者が変えられるのは、メーターパネル写真（再アップロード）、消費カロリー、走行距離、運動時間、運動した日時である。平均速度は編集保存時に常に走行距離÷運動時間（時）で再計算し、利用者は直接変更できない。撮影日時は写真再アップロード時に決め直し、写真を変えない編集では維持する。保存日時と作成開始日時は編集で変えない。いずれかの編集保存が成功したときは運動した日時の手変更を真にし、詳細の運動した日時に「（編集済み）」を付ける。写真を再アップロードしたときは作成時と同様に計測値を読み直し、結果を編集の初期値にする。読めない／不完全なときは手打ち案内相当とし手入力で進められる。保存時の平均速度は再計算値を優先する。運動した日時の編集 UI は全文日時表示と DateTime Picker とする。

値の入り方は 2 通りある。

- メーターパネルを撮影し、読み取りエンジンで解析する。
- 手打ちする。読み取りエンジンが使えないとき、読み取りで走行距離、運動時間、消費カロリーが揃わないとき、運動時間が 0 のとき、読み取りミスを調整するときに使う。

読み取りエンジンは、1 回の読み取りにつき次の排他規則で 1 つだけ選ぶ。両エンジンの併用・項目マージはしない。走行距離、運動時間、消費カロリーが揃い、運動時間が 0 より大きいときは、その結果を手打ちの初期値にする。運動時間が 0 の読み取りは、揃った結果にしない。平均速度がパネルに無いことは失敗理由にしない。平均速度は常に走行距離と運動時間から計算する（パネル値は不採用）。運動時間が 0 より大きいときに計算し、運動時間が 0 のときは計算しない。

| 条件 | エンジン |
| --- | --- |
| LLM が画像付き読み取りで ready | iOS: Foundation Models / Android: Gemini Nano |
| 上記以外（モデル未ダウンロードでなお未準備、画像入力非対応、非対応端末など） | 空間 OCR エンジン（iOS Vision / Android ML Kit ＋空間レイアウト推論） |

選んだエンジンが使えない・失敗したとき、走行距離・運動時間・消費カロリーが揃わないとき、運動時間が 0 のとき、または読み取り全体が 30 秒を超えたときは、手打ちする。読めた走行距離、運動時間、消費カロリーを手打ちの初期値にする。平均速度はパネル値を使わず、運動時間が 0 より大きいときは計算した値を初期値にする。運動時間が 0 のときは平均速度を計算しない。読み取り結果のメッセージ区分と手打ち案内の要否はドメインの言葉「手打ち案内」に従う。

モデル未ダウンロードが検出できるときはモデル未ダウンロード誘導を出す。誘導後も未準備のままなら、当該読み取りの自動エンジンは空間 OCR とする（LLM とは同時に使わない）。画像入力非対応のときは誘導対象外とし、空間 OCR にフォールバックする。通常経路では LLM が ready のときは結果が不完全でも空間 OCR へ落とさない。デバッグの空間 OCR 強制が ON のときはこの限りではなく、空間 OCR のみを試す（使えなければ手打ち。LLM には戻さない）。誘導の出方は強制スイッチに依存しない。

平均速度は、常に走行距離と運動時間から次の式で求める。パネルから読めた平均速度は採用しない。手入力・変更の UI は出さない（表示のみ）。走行距離または運動時間の変更で再計算する。運動時間が 0 以下、または距離／時間が揃わないときは計算しない。

```text
平均速度 (km/h) = 走行距離 (km) / 運動時間 (時)
```

運動時間は時、分、秒を時に直してから割る。

## 期間集計

期間の境界は、端末の現地時刻で切る。運動した日時を端末の現地時刻へ直した日時で、運動履歴を期間へ振り分ける。

| 期間 | 境界 |
| --- | --- |
| 本日 | 現地日付の 0:00 から、翌日 0:00 の直前まで |
| 今週 | 月曜 0:00 から、次の月曜 0:00 の直前まで |
| 今月 | その月の 1 日 0:00 から、翌月 1 日 0:00 の直前まで |

期間集計が合計するのは次の 3 つである。

- 走行距離
- 消費カロリー
- 運動時間

集計期間は利用者が選ぶ。ホームが最初から示す切り口は、本日、今週、今月の 3 つである。利用者が選ぶ期間も、同じ現地時刻で切る。

運動履歴を編集または削除したあとは、期間集計をやり直す。

## ヘルスサービス

CogLog からヘルスサービスへ書くのは、運動の種類と、運動履歴の次の 3 つである。

- 種類はサイクリング
- 走行距離
- 運動時間
- 消費カロリー

書き込みに成功した運動履歴は、ヘルスサービス上のサイクリング 1 件に対応する。対応するサイクリングがあるとき、運動履歴の編集はそのサイクリングの更新、削除はそのサイクリングの削除である。

ヘルスサービスとの完全な同期は必要としない。書き込み、更新、削除が失敗しても、CogLog の運動履歴の保存、編集、削除は完了する。失敗した反映をやり直す振る舞いは持たない。

CogLog がヘルスサービスから読む身体の指標は次のとおり。入力元はヘルスサービスである。

| 指標 | 単位 | ヘルスコネクト | Apple ヘルスケア |
| --- | --- | --- | --- |
| 体重 | kg | WeightRecord | bodyMass |
| 体脂肪率 | % | BodyFatRecord | bodyFatPercentage |
| 除脂肪体重 | kg | LeanBodyMassRecord | leanBodyMass |

身体の指標の単位系も、あとから追加できる余地を残す。追加する単位系の中身は、この文書に書いてから実装する。

CogLog は、読んだ体重、体脂肪率、除脂肪体重を保存しない。推移を表示するときにヘルスサービスから読む。許可が無いとき、または許可が撤回されたあとは、その指標の点を置かない。指標の削除は、ヘルスサービス側の削除に従う。

同じ現地日付に指標が複数あるときは、計測日時が最も遅い値をその日の値にする。

## 推移

推移では、利用者が選んだ期間について、運動と身体の指標を比較グラフで示す。導線はボトムナビの左から 3 番目（ホーム、メーター記録の次）である。

| 期間 | 日数（本日を含む） | 点の間隔 |
| --- | --- | --- |
| 過去 30 日 | 30 日 | 1 日ごと |
| 過去 3 カ月 | 90 日 | 7 日ごと |
| 過去半年 | 182 日 | 14 日ごと |
| 過去 1 年 | 365 日 | 28 日ごと |

初期表示の期間は過去 30 日である。画面上の比較プリセットは次の 3 つだけとし、従来の運動／身体グループ切替と単一指標選択は持たない。初期の比較は「消費カロリー × 体脂肪率」である。同一プロセス内では最後に選んだ比較を維持し、永続化しない。

| 比較 | 同時表示する指標 | 値軸 |
| --- | --- | --- |
| 消費カロリー × 体重・除脂肪体重 | 消費カロリー、体重、除脂肪体重 | 異単位のため二重 Y 軸（kcal と kg）。体重と除脂肪体重は同一軸（kg） |
| 消費カロリー × 体脂肪率 | 消費カロリー、体脂肪率 | 二重 Y 軸（kcal と %） |
| 運動時間 × 走行距離 | 運動時間、走行距離 | 二重 Y 軸（分と km） |

バケットの揃えは、今日を終点に選んだ間隔で過去方向へ区切る。期間先頭側に割り切れない端数があるときは、期間の最も古い側を短いバケットにする。各点の代表日付はバケットの末尾日（今日側）である。端数バケットもその末尾日を代表日付とする。

過去 30 日・1 日ごとのときの点の意味:

| 指標 | 1 日の点 |
| --- | --- |
| 運動時間 | その日の運動履歴の合計 |
| 走行距離 | その日の運動履歴の合計 |
| 消費カロリー | その日の運動履歴の合計 |
| 体重 | その日の最終の計測値 |
| 体脂肪率 | その日の最終の計測値 |
| 除脂肪体重 | その日の最終の計測値 |

7 / 14 / 28 日ごとの 1 点は、そのバケット区間に入る値を集約する。運動は区間内の合計（履歴が無ければ点なし）。身体は区間内の計測のうち計測日時が最も遅い値（計測が無ければ点なし）。

運動履歴が無い日（または区間）は、運動時間、走行距離、消費カロリーの点を置かない。身体の指標が無い日（または区間）は、その指標の点を置かない。線は指標ごとに引く。点が 0 個または 1 個の指標は線を引かない。

- 日次（1 日ごと）: 代表日（現地日付）が隣り合う区間は実線。あいだに点の無い日がある区間は点線。空いた日に点は置かない。
- 間引き（7 / 14 / 28 日ごと）: 表示上となり合う 2 点について、バケット列上で隣り合う（間に空バケットが無い）なら実線、間に空バケットがあれば点線。

グラフ描画は Syncfusion Charts を用いる。異単位の系列は左右の Y 軸に分け、軸または凡例付近に単位を出す。同単位の系列は同一 Y 軸とする。系列の判別のため、指標名と系列色の凡例を常に出す。ツールチップで値と代表日付を示す。

推移タブはヘルス許可の状態にかかわらず常に表示する。身体指標を含む比較（消費カロリー × 体重・除脂肪体重、消費カロリー × 体脂肪率）の選択時に、明示ボタンで体重・体脂肪率・除脂肪体重をまとめて許可リクエストする（自動では出さない）。運動時間 × 走行距離の比較では許可導線を出さない。未許可の指標の点は置かない。系列の読込に失敗したときは、表示中のバケットと系列を空にし、比較を問わず再試行できる。許可リクエストを一度実行しても granted にならないとき（iOS の unknown 含む）は、許可ボタンを隠し、身体を含む比較で OS の設定画面を開く導線を付ける。Android で一部指標だけ許可されているときは、許可済み指標の点だけを置き、未許可分の再リクエストボタンを残す。

Android ではヘルスの履歴許可が無いとき、身体指標の読取開始を直近 30 暦日に切り詰める。過去 90 / 182 / 365 日の期間では、それより古い計測に点を置けない。境界をまたぐバケットも取得できた範囲だけで集約する。身体指標の許可済みでも履歴許可が無く、身体を含む比較を選んでいるときは、履歴許可を再要求する導線を出す。許可リクエスト時には履歴許可もあわせて要求する。

データを取り直す契機は、画面を表示するたび、および期間を変更したときである。このとき運動系列と身体系列をまとめて読み込む。比較プリセットの切替では再取得せず、表示する系列だけを切り替える。
